01 / THE PROJECT

에이전트를 조종하는 게임이 아니라
에이전트의 일을 읽게 하는 표면

Pixel Agents는 코딩 에이전트의 판단이나 도구 결과를 바꾸지 않습니다. Claude Code가 이미 내보낸 hook event와 JSONL transcript를 관찰하고, 이를 공통 AgentEvent로 정규화해 캐릭터의 활동 상태로 표현합니다. 쓰기 도구를 사용하면 책상에서 타이핑하고, 읽기 도구를 사용하면 읽는 동작을 하며, 입력이나 승인이 필요하면 말풍선을 띄웁니다.

핵심 제품은 픽셀 아트가 아니라, 보이지 않던 여러 에이전트의 상태를 한 화면의 공간적 문법으로 바꾸는 런타임입니다.

host: server/src/cli.ts

02 / OBSERVATION

두 관찰 경로를 하나의
AgentEvent로 정규화한다

기본 경로는 Claude Code hook입니다. 설치된 hook script가 SessionStart, PreToolUse, PermissionRequest, Stop 같은 event를 로컬 서버로 POST합니다. JSONL transcript 감시는 hook이 주지 않는 안정적인 tool ID, 진행 정보와 외부 세션 탐색을 보완합니다.

원시 Claude 필드인 tool_name, tool_input, agent_type은 provider 경계에서만 읽습니다. 이후 런타임은 toolStart, toolEnd, turnEnd, permissionRequest 같은 공통 event만 다룹니다.

HOOKS · PRIMARY 즉시성 높은 lifecycle 신호 Claude → claude-hook.js → HTTP POST
TRANSCRIPT · COMPLEMENT tool ID, progress, session 파일 ~/.claude/projects/**.jsonl

근거: claude.ts · transcriptParser.ts

04 / PROTOCOL

화면은 원시 hook JSON을
직접 해석하지 않는다

wire contract의 원전은 core/asyncapi.yaml입니다. 생성된 ServerMessage에는 agent 생성·종료, tool 시작·완료, permission, team metadata, token usage, layout과 asset load가 포함됩니다. 반대 방향의 ClientMessage는 agent 실행·focus·종료, layout 저장, 설정과 asset directory 변경을 표현합니다.

VS Code는 항상 연결된 PostMessageTransport를 사용하고, standalone은 연결 상태와 재접속, 전송 대기 queue를 가진 WebSocketTransport를 사용합니다.

05 / TEAM & SUBAGENT

짧은 subagent와 지속되는 teammate를 구분한다

WITHIN A TURN

Ephemeral subagent

Task 또는 일반 Agent tool에 묶인 임시 캐릭터입니다. parent tool ID를 identity로 사용하고 tool이 끝나면 함께 정리됩니다.

ACROSS TURNS

Persistent teammate

background teammate spawn과 Claude team metadata를 확인해 별도 agent로 연결합니다. lead, teammate name, team lifecycle을 유지하며 한 turn의 tool 정리와 분리합니다.

중복 캐릭터 방지

background Agent 호출이 실제 teammate인 경우에는 일반 subagent 캐릭터를 동시에 만들지 않습니다. 같은 tool 이름이라도 run_in_background와 team metadata를 함께 봅니다.

근거: TeamProvider · Claude team implementation · webview routing

06 / OFFICE ENGINE

캐릭터는 상태표가 아니라
작은 2D world 안에서 움직인다

오피스는 DOM sprite 목록이 아니라 매 frame 갱신되는 Canvas 2D scene입니다. requestAnimationFrame loop가 OfficeState.update()와 renderFrame()을 호출합니다. 16px tile grid에서 wall·void·furniture를 피하는 4방향 BFS pathfinding으로 자리와 이동 경로를 계산합니다.

캐릭터 상태는 IDLE, WALK, TYPE 세 가지입니다. agent가 active가 되면 지정된 seat로 이동하고, 현재 tool이 읽기 계열이면 typing 대신 reading sprite를 사용합니다. idle 상태에서는 오피스를 돌아다니다 쉽니다.

IDLE대기 · 배회 → activity WALKBFS로 자리 이동 → seated TYPE읽기 · 쓰기 animation → turn end WAITING말풍선 · 알림

근거: gameLoop.ts · tileMap.ts · characters.ts

09 / TRUTH BOUNDARY

현재 구현과 제품 비전을 구분해서 읽는다

현재 소스에서 확인됨

  • Claude Code hook와 transcript의 공통 AgentEvent 정규화
  • VS Code extension과 standalone CLI의 공유 runtime
  • tool, waiting, permission과 team/subagent 시각화
  • typed AsyncAPI message와 두 transport 구현
  • Canvas 2D, BFS pathfinding, layout editor와 asset manifest

페이지가 주장하지 않음

  • Codex·Gemini 등 두 번째 실제 provider가 이미 제공된다는 주장
  • Pixel Agents가 Claude의 판단이나 tool result를 조작한다는 주장
  • 말풍선에서 Claude permission을 승인·거절한다는 주장
  • standalone이 Claude process를 대신 시작한다는 주장
  • 모든 외부 asset의 라이선스가 프로젝트 MIT와 같다는 주장
현재 provider 현실

공통 HookProvider 계약은 존재하지만 bundled provider는 Claude Code 하나입니다. 소스 주석도 실제 두 번째 provider가 도착하기 전에 speculative abstraction을 늘리지 않겠다고 명시합니다.
